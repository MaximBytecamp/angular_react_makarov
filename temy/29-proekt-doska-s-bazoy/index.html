§2Обязательные требования

Работа принимается, если выполнены все пункты. Справа — глава, где разобран нужный механизм.

  • Шапка, форма, карточка и категории — своего варианта, как в проекте модуля 1П1
  • Своя коллекция в PocketBase: поля как у requests, варианты категории — свои, обязательные поля отмечены Required2.2
  • Правила коллекции как в главе 2.2: чтение всем, создать — только со статусом «Новая», изменить — без названия, места и подробностей, удалить — только «Готово»2.2
  • В коллекции не меньше пяти своих заявок разных статусов2.2
  • Список загружается из PocketBase, пока его нет — надпись о загрузке2.3
  • Если PocketBase остановлен, на доске сообщение и кнопка «Повторить»; после запуска сервера кнопка загружает список2.3
  • Добавление, смена статуса и удаление отправляются на сервер и сохраняются после F52.3
  • Код данных — в хуке useRequests; в App.tsx нет fetch и useEffect загрузки2.4
  • Заявка, добавленная в одном окне, появляется в другом без F5 и без повторов2.5
  • В проекте нет localStorage и файла storage.ts2.3
  • ИИ-диспетчер работает со своими категориями: категория от модели записывается в свою коллекцию, в Telegram приходит сообщение с кнопкой «Взять»А2
  • Нажатие «Взять» переводит заявку своей коллекции в «В работе», доска показывает это без F5А2
  • npm run build и npm run lint проходят без ошибок и предупреждений1.1

§3Порядок работы

ДелаемПереносим свой вариант на сервер

  1. Возьмите основу

    Скопируйте папку zayavki после главы 2.5 в новую, например zayavki-obshchezhitie. В новой папке выполните npm install. Остановите доску ИТ-отдела (Ctrl+C в её терминале) и запустите свою: npm run dev. Доска должна работать на порту 5173 — с этого адреса n8n принимает заявки.

  2. Перенесите тексты варианта

    Из своего проекта модуля 1 скопируйте Header.tsx, RequestCard.tsx и RequestForm.tsx в src/components. В requests.ts замените только тип Category на свои четыре категории: остальное в этом файле — из главы 2.5.

  3. Создайте коллекцию

    В панели PocketBase создайте коллекцию с именем своего варианта латиницей, например obshchezhitie, так же, как requests в главе 2.2 §3. В поле category впишите свои четыре категории. Настройте пять правил, как в главе 2.2 §5, и добавьте пять заявок разных статусов.

  4. Подключите доску к своей коллекции

    Имя коллекции записано в двух файлах. Замените requests на имя своей коллекции в api.ts (строка 3) и realtime.ts (строка 12).

  5. Проверьте два окна

    Обновите страницу: на доске заявки своей коллекции. Откройте второе окно и добавьте заявку в первом — она должна появиться в обоих по одному разу.

  6. Проверьте ошибку

    Остановите PocketBase (docker compose stop pocketbase), обновите доску — должны появиться сообщение и кнопка «Повторить». Запустите PocketBase (docker compose start pocketbase) и нажмите «Повторить».

  7. Настройте ИИ-диспетчер

    В n8n откройте процесс «ИИ-диспетчер». В узле Модель замените категории в двух местах: в тексте инструкции (role: 'system') и в списке enum. Замените подпись «Кабинет» в узле Telegram на своё поле места. В узле Категория в базу замените requests в адресе на имя своей коллекции. Сохраните и опубликуйте процесс заново.

  8. Настройте кнопку «Взять»

    В процессе «Кнопка «Взять»» в узле Статус в базу замените requests в адресе на имя своей коллекции. Сохраните и опубликуйте.

  9. Проверьте весь путь

    Добавьте заявку с доски, дождитесь сообщения бота, нажмите «Взять» и проверьте статус на доске. Пройдите список из §2 по порядку. Во втором терминале выполните npm run build и npm run lint.

Почему процессы правятся на месте

Нажатия кнопок забирает из Telegram только один процесс: getUpdates отдаёт каждое нажатие один раз, тому, кто первым спросил. Если опубликованы два процесса «Кнопка «Взять»» с одним ботом, нажатия случайно достаются то одному, то другому. Поэтому для своего варианта правятся процессы со страницы автоматизации, а копии не создаются.

§5Работа с ИИ

Проект выполняется в режиме Р1 из главы 0.5, как проект модуля 1: ИИ объясняет, код пишет студент, автодополнение ИИ в редакторе отключено. Журнал ai-log.md ведётся так же. Токен бота, номер чата и пароль суперпользователя PocketBase в чат ИИ не вставляются.

Модель qwen2.5:3b в автоматизации — часть продукта, её ответы в журнал не пишутся. В журнал записывается, если менялась инструкция модели: что было, что стало и сколько заявок из проверочных она после этого разобрала верно.

§6Сдача и защита

ДелаемГотовим работу к сдаче

  1. Проверьте сборку

    Во втором терминале выполните обе команды. Ошибок и предупреждений быть не должно.

  2. Проверьте, что секретов нет в коде

    В VS Code нажмите Ctrl+Shift+F и найдите в папке проекта начало своего токена и пароль суперпользователя PocketBase. Совпадений быть не должно.

  3. Выгрузите процессы n8n

    Откройте каждый из двух процессов, нажмите … рядом с названием и выберите Export JSON. n8n сохранит файл процесса. Учётные данные бота в файл не попадают, номер чата — попадает: перед сдачей сотрите его в файле «ИИ-диспетчера» (поле chatId).

  4. Соберите архив

    Удалите папки node_modules и dist. Упакуйте папку проекта вместе с ai-log.md и двумя файлами процессов. Файл .env из папки avtomatizaciya в архив не кладётся.

  5. Приложите снимки

    Снимок сообщения бота с кнопкой и снимок после нажатия «Взять».

РазбираемсяКак проходит защита

На защите студент запускает PocketBase, n8n и доску на своём компьютере и проходит список из §2: два окна, остановленный сервер, сообщение бота, нажатие кнопки. Затем преподаватель указывает на строки кода и спрашивает, что они делают и почему так написаны. Ответ «так написал ИИ» оценивается как отсутствие ответа. Примеры вопросов:

  • Что ответит PocketBase, если отправить заявку со статусом «Готово», и какое правило за это отвечает?
  • Зачем в эффекте загрузки флажок ignore? Что было бы без него?
  • Почему setLoading(false) стоит после try и catch, а не внутри try?
  • Что изменится, если вызвать useRequests ещё и в шапке?
  • Почему своя новая заявка не появляется на доске дважды?
  • Зачем запросу к модели JSON-схема и что будет без неё?
  • Почему нажатия кнопки обрабатываются раз в 10 секунд, а не сразу?
  • Модель поставила неверную категорию. Что сделает мастер и увидит ли это студент, который отправил заявку?
