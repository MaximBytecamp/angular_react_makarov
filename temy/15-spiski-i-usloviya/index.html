§1Заявки в одном массиве

Сейчас каждая заявка записана в App.tsx отдельным вызовом <RequestCard … />, а её статус хранится в отдельном состоянии: status1, status2, status3. Для четвёртой заявки пришлось бы добавить ещё одно состояние и ещё один вызов карточки. Заявок на доске может быть десятки, и для каждой так не напишешь. Поэтому данные заявок отделяют от разметки: все заявки хранятся одним списком, а разметка описывает одну карточку и повторяется для каждого элемента списка.

Сравнение из жизни

В ИТ-отделе заявки записывают в журнал. Это таблица: каждая строка описывает одну заявку. Графы у всех строк одинаковые — номер, что случилось, кабинет, подробности, статус. Строки журнала пронумерованы по порядку. Массив в программе — такой журнал, объект — одна его строка, поля объекта — графы.

Строки журнала нумеруют с единицы, элементы массива — с нуля.

Массив — список значений в квадратных скобках через запятую: ['214', '305', '112']. Каждое значение — элемент массива, у элемента есть номер — индекс. Индексы начинаются с нуля: первый элемент — [0], второй — [1]. Число элементов хранит свойство length.

Объект — набор пар «имя: значение» в фигурных скобках: { id: 1, title: 'Не работает проектор' }. Пары называются полями (или свойствами), значение поля читают через точку: request.title. Объектами в главе 1.3 были props карточки.

§2Карточки из массива: map и key

У массива есть метод map («сопоставить»). Он проходит по элементам по очереди, для каждого вызывает функцию, которую ему передали, и собирает результаты в новый массив той же длины. Исходный массив при этом не меняется.

Сравнение из жизни

Секретарь получает журнал заявок и стопку пустых бланков. Для каждой строки журнала он берёт бланк и переписывает в него графы этой строки. Сколько строк в журнале, столько получается заполненных бланков, а журнал остаётся как был. Метод map — секретарь, функция в скобках — правило, как заполнить бланк по одной строке.

Секретарь может ошибиться или пропустить строку. map вызывает функцию для каждого элемента по порядку и всегда возвращает массив той же длины.

Пример без React: из массива номеров кабинетов получается массив подписей.

Функция (room) => 'каб. ' + room — стрелочная функция из главы 1.4, на этот раз с параметром room. Метод map вызывает её три раза: с '214', с '305' и с '112'. Каждый раз room получает очередной элемент, а то, что записано после стрелки, становится элементом нового массива. Комментарий после // показывает, что напечатает console.log.

В React функция для map возвращает разметку карточки. Массив разметок React выводит на страницу подряд, как если бы карточки были записаны в коде одна за другой.

Предупреждение о key

Карточки выводятся, но в консоли браузера появилась ошибка. Откройте консоль (F12, вкладка Console) и обновите страницу.

Сообщение Each child in a list should have a unique "key" prop переводится как «у каждого элемента списка должен быть уникальный prop key». Вторая строка уточняет место: список выводится внутри section, а передан он из компонента App. То же самое находит линтер до запуска страницы:

Адрес App.tsx:29:21 — строка 29, символ 21: начало стрелочной функции внутри map. Слово iterator в сообщении означает функцию, которая вызывается для каждого элемента массива.

Ключ (key) — особый атрибут элемента в списке, по которому React отличает элементы друг от друга. В компонент он не передаётся и в props карточки не появляется: его читает сам React. Когда массив меняется — заявку убрали, добавили или переставили, — React сравнивает новый список с прежним по ключам. Карточку с тем же ключом он считает той же самой: обновляет её текст и сохраняет её состояние. Карточку с новым ключом он создаёт заново. Карточку, ключа которой больше нет, удаляет со страницы.

Ключ должен быть разным у элементов одного списка и не должен меняться, пока элемент существует. Для заявок такой признак уже есть — поле id.

Замените в App.tsx функцию handleNext вариантом ниже и сохраните. Нажмите «Взять в работу» в первой карточке.

Метод findIndex возвращает индекс первого элемента, для которого условие истинно, — здесь индекс заявки с нужным id. Следующая строка записывает в поле status этой заявки следующий статус. Затем новый статус печатается в консоль, и тот же массив передаётся в setRequests.

Статус внутри массива изменился — консоль это подтверждает. Страница осталась прежней. Причина — в правиле, по которому React запускает новую отрисовку. Получив значение в setRequests, React сравнивает его с текущим значением состояния. Для массивов и объектов проверяется, тот же это массив в памяти или другой; поля внутри не сравниваются. В setRequests передан тот же массив requests, в котором поменяли одно поле, поэтому React считает, что состояние не изменилось, и функцию App заново не вызывает.

Сравнение из жизни

Секретарь принимает на подпись только новые экземпляры приказа. Если вернуть ему тот же лист, на котором ручкой исправлено одно слово, он видит знакомый лист и откладывает его: этот приказ уже подписан. Чтобы правка дошла до подписи, приказ перепечатывают на новый лист.

Секретарь заметит исправление, если присмотрится. React содержимое не просматривает и проверяет только, тот же это массив или другой.

§4Условный вывод

Сравнение из жизни

Над дверью студии висит табло «Идёт запись». Оно горит, только когда включён микрофон, и гаснет вместе с ним; надпись на табло всегда одна. Светофор на переходе показывает один из двух сигналов: красный или зелёный. В интерфейсе встречаются оба случая: элемент либо выводится, либо нет, или выводится один из двух вариантов.

Погасшее табло остаётся на стене. Элемент, который по условию не выводится, на странице отсутствует совсем.

В пяти карточках подробности занимают половину высоты списка. Удобнее показывать их по кнопке «Подробнее». А у готовых заявок кнопка «Завершить» сейчас выключена и бесполезна; на её месте нужна кнопка «Убрать с доски». В обоих случаях часть разметки выводится только при каком-то условии. Это называется условным выводом (conditional rendering).

В JSX условие записывают выражением, потому что if внутри фигурных скобок не допускается (глава 1.4). Используют две записи:

ЗаписьЧто выводитКогда использовать
{условие && <p>…</p>}Абзац, если условие истинно; ничего, если ложноЭлемент либо есть, либо его нет
{условие ? <A /> : <B />}A, если условие истинно; B, если ложноВыбор одного из двух вариантов

Знак && — логическое «и». Выражение a && b сначала проверяет a. Если a ложно, результат — само a, и b даже не вычисляется. Если a истинно, результат — b. В JSX это работает так. При open, равном true, выражение {open && <p>…</p>} даёт абзац. При false оно даёт значение false, а false React на страницу не выводит.

Строка {requests.length === 0 && <p className="empty">Заявок нет</p>} выводит сообщение, когда в массиве не осталось заявок. Пока заявки есть, сравнение даёт false, и сообщения на странице нет.

Число слева от &&

Короткая запись {requests.length && …} выглядит похоже, но при пустом массиве выводит на страницу цифру 0. Выражение 0 && … равно 0, а число React выводит, в отличие от false. Слева от && ставят сравнение, которое даёт true или false: requests.length === 0, requests.length > 0.

§5Фильтр по статусу

Над списком появляются четыре кнопки: «Все», «Новая», «В работе», «Готово». Выбранная кнопка закрашена, и в списке остаются только заявки с этим статусом. Для этого в App нужно ещё одно состояние — выбранный фильтр — и список видимых заявок, вычисленный из двух состояний.

Сравнение из жизни

В Google Таблицах или Excel фильтр по столбцу «Статус» скрывает строки с другими статусами. Сами строки остаются в таблице: если снять фильтр, они снова видны. Состояние filter работает так же: массив requests не меняется, меняется только то, какие заявки выводятся.

В таблице фильтр настраивают мышью в меню столбца. Здесь правило отбора записано в коде, а кнопки только меняют значение filter.

  1. Добавьте стили кнопок

    В конец src/index.css добавьте правила и сохраните.

  2. Замените содержимое App.tsx
  3. Проверьте фильтр

    Нажмите «Новая». Затем нажмите «Все», уберите заявку про принтер и нажмите «Готово».

Разбор App.tsx

type Filter = 'Все' | Status описывает значение фильтра: «Все» или один из трёх статусов. Массив FILTERS перечисляет кнопки в нужном порядке. Он объявлен вне App, потому что не меняется и не зависит от состояния. Имя записано заглавными буквами — так в JavaScript принято обозначать постоянные наборы значений.

useState<Filter>('Все') создаёт второе состояние. Тип в угловых скобках нужен по той же причине, что в главе 1.4: без него TypeScript вывел бы из 'Все' тип string.

Строка 16 вычисляет visible — заявки, которые нужно показать. Если выбран фильтр «Все», это весь массив requests. Иначе — результат filter по статусу. visible не хранится в состоянии. Как и newCount, он вычисляется при каждой отрисовке из двух состояний — requests и filter. Удаление заявки и смена фильтра меняют разные состояния, а visible после любого из них пересчитывается сам.

Кнопки фильтра тоже выводятся через map — из массива FILTERS. Ключом служит сама строка f: названия фильтров разные и не меняются. Атрибут className={f === filter ? 'active' : ''} — условный вывод класса: у выбранной кнопки класс active, у остальных пустая строка. По классу active правило .filters button.active закрашивает кнопку синим.

Доска готова. Остаётся проверить на опыте, что будет, если ключом взять номер элемента в массиве.

§6Опыт: ключ — номер в массиве

Функция для map может принимать второй параметр — индекс элемента. Его иногда используют как ключ: key={index}. Ошибка о key в консоли исчезает, и пока список не меняется, всё работает. Опыт показывает, что происходит при удалении заявки.

  1. Замените ключ

    В App.tsx измените две строки внутри visible.map, как показано ниже, и сохраните.

  2. Раскройте четвёртую карточку

    Обновите страницу, чтобы вернуть все пять заявок. Нажмите «Подробнее» в четвёртой карточке — «Не включается компьютер».

  3. Уберите третью заявку

    Нажмите «Убрать с доски» у заявки про принтер.

Раскрытой оказалась другая заявка. Состояние open хранится в React для каждой карточки, а React находит карточку по ключу. До удаления «Не включается компьютер» стояла на месте [3] и имела ключ 3. После удаления принтера все следующие заявки сдвинулись на одно место: «компьютер» получил индекс 2, «мышь» — индекс 3. В новом списке снова есть ключ 3, и React отдаёт карточке с этим ключом прежнее состояние open = true. Карточку с ключом 4 он удаляет: такого ключа в новом списке нет.

Сравнение из жизни

В гардеробе пальто выдают по номерку, который висит на крючке вместе с пальто. Допустим, вместо номерков считают крючки по порядку: «ваше — четвёртое слева». Если одно пальто снять и сдвинуть остальные, четвёртым слева окажется чужое. Индекс — порядковое место, id — номерок.

В гардеробе пальто сами не сдвигаются. В массиве после удаления элемента все следующие элементы получают индекс на единицу меньше.

  1. Верните ключ id

    Верните в App.tsx строки {visible.map((r) => ( и key={r.id}, сохраните и повторите опыт: обновите страницу, раскройте «Не включается компьютер», уберите принтер.

Правила выбора ключа:

  • значение разное у всех элементов одного списка;
  • значение не меняется у элемента, пока он существует;
  • значение берётся из самих данных — обычно это id из базы или с сервера.

Индекс подходит, только если список никогда не меняется: в нём не удаляют, не добавляют в начало или середину и не сортируют элементы. Случайное число вида key={Math.random()} не подходит совсем: при каждой отрисовке ключи новые, и React пересоздаёт все карточки, теряя их состояние.

§8Проверьте себя

Что возвращает [1, 2, 3].map((n) => n * 10) и меняется ли исходный массив?

Новый массив [10, 20, 30]. Исходный массив остаётся [1, 2, 3]: map его не меняет.

Чем filter отличается от map?

map возвращает массив той же длины, где каждый элемент — результат функции. filter возвращает массив из исходных элементов, для которых функция вернула true. Он такой же длины или короче.

Зачем React нужен key и почему для заявок выбран id?

По ключу React находит, какая карточка нового списка соответствует какой карточке прежнего. Такую карточку он обновляет и сохраняет её состояние. id у каждой заявки свой и не меняется при удалении, добавлении и сортировке, а индекс при удалении сдвигается.

Почему после requests[0].status = 'Готово'; setRequests(requests) страница не обновляется?

React сравнивает новое значение состояния с текущим и для массива проверяет, тот же это массив или другой. Передан тот же массив, поэтому новой отрисовки нет. Нужно передать новый массив, построенный через map.

Что даст { ...r, room: '301' }, если r — первая заявка?

Новый объект со всеми полями первой заявки, у которого room равен '301'. Сам r не изменится.

Почему visible не хранится в отдельном состоянии?

Он полностью вычисляется из двух состояний — requests и filter. При каждой отрисовке App он пересчитывается и всегда соответствует им. Отдельное состояние пришлось бы обновлять при удалении заявки, смене статуса и смене фильтра, и его легко забыть обновить.

Добавьте к фильтру счётчик: «Новая (3)», «В работе (1)». Что нужно изменить?

В FILTERS.map вычислить число заявок для каждой кнопки и вывести его рядом с названием:

  1. внутри функции для map посчитать const count = f === 'Все' ? requests.length : requests.filter((r) => r.status === f).length; функцию придётся записать с фигурными скобками и return;
  2. в кнопке вывести {f} ({count});
  3. проверить, что числа меняются после «Взять в работу» и «Убрать с доски».

Итог главы

Однотипные данные хранят массивом объектов, а разметку описывают для одного элемента и выводят для всех методом map. Каждому элементу списка нужен атрибут key — постоянный и уникальный признак из данных, обычно id. По нему React сопоставляет новый список с прежним и сохраняет состояние карточек. Индекс в качестве ключа ломает это сопоставление при удалении и перестановке. Массив и объект из состояния заменяют новыми. Новый массив строят через map или filter, изменённый объект — через оператор расширения { ...r, поле: значение }. Если изменить массив на месте, React не запустит отрисовку. Условный вывод записывают выражениями: && — элемент есть или нет, тернарный оператор — один из двух вариантов. Значения, которые вычисляются из состояния, как newCount и visible, в состояние не записывают. Доска выводит заявки из массива, раскрывает подробности, убирает готовые заявки и фильтрует список по статусу.
