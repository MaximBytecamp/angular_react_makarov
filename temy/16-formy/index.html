§1Категория в данных заявки

В форме есть выпадающий список «Категория»: компьютер, проектор, принтер, интернет. А в данных заявки категории нет — в requests.ts у заявки только номер, название, кабинет, подробности и статус. Прежде чем подключать форму, в данные добавляется поле category, а карточка начинает его показывать.

ДелаемДобавляем категорию

  1. Замените содержимое requests.ts

    Откройте src/requests.ts, выделите весь текст (Ctrl+A), вставьте код ниже и сохраните. Изменённые строки подсвечены.

  2. Замените содержимое RequestCard.tsx

    Карточка получает категорию и показывает её рядом с кабинетом.

  3. Замените содержимое App.tsx

    Изменилась одна строка: карточке передаётся category={r.category}.

  4. Проверьте страницу

    У каждой заявки рядом с кабинетом указана категория: «каб. 214 · Проектор».

РазбираемсяЧто добавилось в requests.ts

  1. 1

    «Категория бывает только одной из четырёх». Тип записан так же, как Status: строки через черту |, которая читается как «или». Значения те же, что в выпадающем списке формы.

  2. 2

    У каждой заявки теперь есть поле category. TypeScript проверит, что оно есть у всех пяти заявок в массиве ниже: если пропустить, в этой строке массива появится красное подчёркивание.

  3. 3

    «Что приходит из формы». Новый тип NewRequest — заявка, какой её заполняет человек: название, кабинет, категория, подробности. Номера id и статуса тут нет: их назначает доска при добавлении заявки.

Данные готовы принять категорию. Следующий шаг — научить форму передавать то, что в неё ввели.

§2Поля под управлением React

РазбираемсяГде сейчас хранится введённый текст

Сравнение из жизни

Посетитель заполняет заявление сам, ручкой, у себя на коленях. Секретарь не видит, что там написано, пока посетитель не отдаст лист. По-другому: посетитель диктует, а секретарь сразу печатает каждое слово в журнал на экране. Тогда секретарь в любой момент знает, что уже сказано, и может, например, заметить пустую графу.

Секретарь печатает со своей скоростью. В React каждая нажатая клавиша сразу записывается в состояние, и поле показывает то, что записано.

Сейчас форма работает как заявление на коленях. Текст, который набирает пользователь, хранит само поле браузера. В коде формы нет ни одной переменной с этим текстом, поэтому React его не получает. Чтобы заявку можно было добавить в список, текст каждого поля должен лежать в состоянии React.

Управляемое поле (controlled input) — поле ввода, текст которого хранится в состоянии. У него два атрибута:

  • value={title} — «показывай в поле то, что лежит в title»;
  • onChange={…} — «когда пользователь меняет текст, вызови эту функцию». Функция записывает новый текст в состояние.

Опыт ниже показывает, почему нужны оба.

ДелаемОпыт: value без onChange

  1. Замените содержимое RequestForm.tsx версией для опыта

    У поля «Что случилось» появились состояние title и атрибут value, а onChange нет. Замените весь текст src/components/RequestForm.tsx и сохраните.

  2. Попробуйте набрать текст

    Откройте консоль браузера (F12, вкладка Console) и обновите страницу (F5). Щёлкните по полю «Что случилось» и наберите любое слово. Поле остаётся пустым, в консоли — ошибка.

РазбираемсяПочему текст не набирается

  1. 1

    Память для текста поля, начальное значение — пустая строка ''. Из пары, которую возвращает useState, взята только первая часть: функции для изменения в опыте нет.

  2. 2

    value={title} говорит: «в поле всегда то, что лежит в title». В title пустая строка, и поменять её некому. Пользователь нажимает клавишу, браузер на мгновение добавляет букву, а React тут же возвращает поле к значению из состояния — к пустой строке.

Сообщение в консоли переводится так: «вы задали полю формы prop value без обработчика onChange. Поле будет только для чтения». Дальше React предлагает два выхода: defaultValue, если поле должно хранить текст само, или onChange. Для доски нужен второй: текст должен попасть в состояние.

ДелаемПодключаем все поля к состоянию

  1. Замените содержимое RequestForm.tsx

    В этой версии у каждого поля своё состояние, value и onChange. Под полями — временная строка, которая показывает, что лежит в состоянии. Замените весь текст и сохраните.

  2. Заполните форму

    Обновите страницу. Под полями строка «Сейчас в состоянии: «», каб. , Компьютер». Наберите в поле «Что случилось» текст «Не печатает принтер», в поле «Кабинет» — 118, в списке выберите «Принтер». Строка под полями меняется с каждой буквой.

РазбираемсяКак буква попадает в состояние

  1. 1

    Память для поля «Что случилось», в начале пустая. Так же ниже — для кабинета и подробностей.

  2. 2

    Память для категории. Начальное значение — «Компьютер», первый вариант списка. <Category> говорит TypeScript, что здесь лежит одна из четырёх категорий.

  3. 3

    «Показывай в поле содержимое title».

  4. 4

    «Когда текст в поле меняется, запиши его в title». React вызывает стрелочную функцию с параметром event. Это объект события: в нём браузер описывает, что произошло. event.target — поле, где это случилось. event.target.value — текст, который в нём сейчас набран.

  5. 5

    То же для списка. В поле value у списка лежит строка, а в память можно положить только одну из четырёх категорий. Запись as Category говорит TypeScript: «здесь точно категория». Это верно, потому что вариантов в списке только четыре и все они из типа Category.

  6. 6

    Временная строка: показывает, что сейчас в состоянии. Она нужна только для проверки и в следующей версии формы исчезнет.

Пошаговый разбор ниже показывает, что происходит, когда пользователь нажимает одну клавишу в поле «Что случилось».

Текст всех полей лежит в состоянии формы. Следующий шаг — по кнопке «Отправить заявку» передать его в App и добавить заявку в список.

§3Отправка заявки

РазбираемсяЧто браузер делает при отправке формы

Кнопка «Отправить заявку» записана с type="submit". Нажатие на неё вызывает у формы событие отправки (submit). Без нашего кода браузер на это событие отправляет данные формы по адресу из её настроек и загружает страницу заново. Так работали сайты до JavaScript: каждое отправленное заявление — новая страница с сервера. Для доски это значит, что страница перезагрузится, а состояние React — заявки, статусы, введённый текст — вернётся к начальному.

event.preventDefault() — «не выполняй действие по умолчанию». Его вызывают первой строкой обработчика отправки, и браузер не перезагружает страницу. Дальше обработчик передаёт данные формы в App через prop-функцию onAdd. Так же в главе 1.4 карточка сообщала о щелчке через onNext.

ДелаемПодключаем отправку

  1. Замените содержимое RequestForm.tsx

    Добавлены prop onAdd, функция handleSubmit и onSubmit у формы; временная строка убрана. Замените весь текст и сохраните.

    После сохранения App.tsx подчеркнётся красным: форме теперь нужен prop onAdd. Это исправит следующий шаг.

  2. Замените содержимое App.tsx

    Добавлена функция handleAdd, форма получает её в onAdd.

  3. Заполните форму

    Обновите страницу (F5). Заполните поля: «Не печатает принтер», кабинет 118, категория «Принтер», подробности «Принтер в коридоре мигает красной лампой.».

  4. Отправьте заявку

    Нажмите «Отправить заявку». Новая заявка появилась первой в списке, в шапке «Новых заявок: 4», поля формы очистились. Страница не перезагружалась: остальные заявки и фильтр на месте.

РазбираемсяЧто делает форма при отправке

  1. 1

    Кроме useState из React берётся тип SubmitEvent — описание события отправки. Слово type отмечает, что это только тип.

  2. 2

    «Форме нужна функция onAdd». Её даст App. Форма вызовет её с новой заявкой типа NewRequest; void значит, что функция ничего не возвращает.

  3. 3

    Обработчик отправки. В скобках — объект события, <HTMLFormElement> уточняет, что событие пришло от формы.

  4. 4

    «Не перезагружай страницу». Без этой строки браузер загрузил бы страницу заново, и новая заявка исчезла бы вместе со всем состоянием.

  5. 5

    «Отдай заявку в App». В фигурных скобках собирается объект из четырёх полей. Запись { title, room, … } — короткая форма { title: title, room: room, … }: если имя поля и имя переменной совпадают, его пишут один раз.

  6. 6

    Очистка формы: в каждое состояние записывается начальное значение. Поля показывают состояние, поэтому тоже становятся пустыми.

  7. 7

    «При отправке формы вызови handleSubmit». Обработчик подключается к самой форме. Форма отправляется и кнопкой, и клавишей Enter в однострочном поле, и обработчик срабатывает в обоих случаях.

РазбираемсяКак App добавляет заявку

Строка 29 собирает полную заявку из того, что пришло из формы. ...data копирует четыре поля формы. Так же оператор расширения копировал поля заявки в главе 1.5. К ним добавляются id и статус «Новая».

Date.now() возвращает число миллисекунд, прошедших с 1 января 1970 года, например 1793210000000. Каждую миллисекунду это число растёт, поэтому у двух заявок, отправленных в разные моменты, номера разные. Номер нужен для ключа key и для кнопок «Взять в работу» и «Убрать с доски».

Строка 30 строит новый массив: [created, ...requests]. Внутри квадратных скобок три точки делают то же, что в фигурных: перекладывают все элементы старого массива в новый. Новая заявка стоит первой, за ней — прежние. Старый массив не меняется, как требует правило из главы 1.5.

requests — прежний массив

id 1id 2id 3id 4id 5

[created, ...requests] — новый массив, новая заявка первой

новаяid 1id 2id 3id 4id 5

    Не заполняя поля, нажмите «Отправить заявку». Первой в списке появилась карточка без названия и без номера кабинета: «каб. · Компьютер».

§4Проверка полей

РазбираемсяЧто проверять

Сравнение из жизни

В окошке приёма заявлений сотрудник сначала смотрит, заполнены ли обязательные графы. Если нет графы «Кабинет», заявление возвращают с пометкой, что дописать, и в журнал его не записывают.

Сотрудник может перечитать заявление и через минуту. Форма проверяет поля в момент нажатия кнопки, до того как заявка попадёт в список.

Без названия и кабинета заявку не выполнить, поэтому эти два поля обязательные. Пустым считается и поле из одних пробелов. Если поле пустое, под полями появляется сообщение, и заявка в App не уходит. Сообщение — ещё одно состояние формы: строка с текстом ошибки, пустая, пока ошибки нет.

ДелаемДобавляем проверку

  1. Добавьте стиль сообщения

    Откройте src/index.css, вставьте правило в самый конец файла и сохраните.

  2. Замените содержимое RequestForm.tsx

    Изменённые строки подсвечены.

  3. Отправьте поле из пробелов

    Обновите страницу (F5). В поле «Что случилось» наберите три пробела, кабинет оставьте пустым и нажмите «Отправить заявку». Под полями появилось сообщение, список не изменился.

  4. Заполните поля и отправьте

    Допишите в поле «Что случилось» «Не открывается сайт колледжа», кабинет 305, категория «Интернет». Нажмите «Отправить заявку». Сообщение исчезло, заявка первая в списке.

РазбираемсяКак работает проверка

  1. 1

    Память для текста ошибки. Пустая строка — ошибки нет.

  2. 2

    «Если название пустое или кабинет пустой…». trim() убирает пробелы в начале и в конце: из ' ' получается ''. Знак || — «или»: условие выполнено, если пусто хотя бы одно поле.

  3. 3

    «…запиши текст ошибки». Форма перерисуется, и сообщение появится под полями.

  4. 4

    return — «на этом закончить». Строки ниже не выполняются: заявка не уходит в App, поля не очищаются, и пользователь не теряет набранное.

  5. 5

    Заявка уходит в App уже без лишних пробелов: title.trim() вместо title. Так « Не открывается сайт колледжа» станет «Не открывается сайт колледжа».

  6. 6

    После удачной отправки сообщение об ошибке стирается.

Строка 71 выводит сообщение: {error !== '' && <p className="form__error">{error}</p>}. Это условный вывод из главы 1.5: абзац есть, когда error не пустая строка, и его нет, когда пустая.

Доска заявок готова: заявки добавляются из формы, меняют статус, убираются и фильтруются. Пока все данные живут только в памяти вкладки браузера: после перезагрузки страницы на доске снова пять заявок из requests.ts.

§6Проверьте себя

Что такое управляемое поле и какие у него два атрибута?

Поле ввода, текст которого хранится в состоянии React. value показывает в поле значение из состояния, onChange вызывает функцию, которая записывает новый текст в состояние.

Почему поле с value, но без onChange, нельзя изменить?

Поле всегда показывает значение из состояния. Изменить это значение некому, и React возвращает поле к нему после каждой нажатой клавиши.

Что делает event.preventDefault() в обработчике отправки?

Отменяет действие браузера по умолчанию — отправку формы с перезагрузкой страницы. Без него страница загрузится заново, и состояние React вернётся к начальному.

Почему обработчик отправки подключают к форме через onSubmit?

Форма отправляется и кнопкой, и клавишей Enter в однострочном поле. Обработчик у формы срабатывает в обоих случаях.

Что получится из [created, ...requests], если в requests пять заявок?

Новый массив из шести заявок: первой created, за ней пять прежних по порядку. Массив requests не изменится.

Зачем в проверке title.trim() === '' нужен trim()?

trim() убирает пробелы по краям. Поле из одних пробелов без trim() прошло бы проверку, и на доске появилась бы заявка без названия.

Сделайте поле «Подробности» тоже обязательным. Что нужно изменить?

Дописать в условие handleSubmit ещё одну проверку и поправить текст сообщения:

  1. if (title.trim() === '' || room.trim() === '' || details.trim() === '');
  2. текст ошибки: «Заполните поля «Что случилось», «Кабинет» и «Подробности».»;
  3. проверить: заявка без подробностей не добавляется, сообщение появляется.

Итог главы

Текст полей формы хранят в состоянии: у управляемого поля value берёт значение из состояния, а onChange записывает в него каждое изменение. Поле с value, но без onChange, становится только для чтения. Отправку обрабатывают у самой формы через onSubmit; первой строкой обработчика вызывают event.preventDefault(), иначе браузер перезагрузит страницу. Данные формы передают родителю через prop-функцию, родитель добавляет номер и статус и строит новый массив [created, ...requests]. Перед отправкой обязательные поля проверяют с trim(); при ошибке записывают текст сообщения в состояние и выходят из обработчика через return. Доска заявок принимает новые заявки из формы, но хранит их только до перезагрузки страницы.
